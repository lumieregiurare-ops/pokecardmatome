# ポケカ速報（ポケモンカードの抽選・予約・新弾・再販情報まとめ）

ポケモンカード（紙のポケカ・ポケポケ）のニュースを集めて、30 分おきに自動で更新する静的サイトです。pokematome を元にしています。`docs/` がサイトルートで、そのままロリポップ（FTP）に置いて公開できます。

- 掲載するのは **見出し・要約の一部・元記事へのリンク・元記事の og:image** のみ（本文の転載はしない）
- 見出しから **抽選・予約の締切**、**発売日・開催日**、**店舗**、**商品名** を機械的に読み取って、抽選ボード・カレンダー・商品別・店舗別のページを作る
- **当サイトはファンによる非公式のまとめサイトで、株式会社ポケモン・任天堂とは関係ありません。**

## 使い方

```bash
npm install          # esbuild / sharp（ビルド用のみ）
npm run collect      # ニュースを収集して docs/data/news.json と静的ページを更新
npm run build        # site/ を最小化して docs/ に出力
npm start            # ビルドしてローカルサーバー（http://localhost:3290）
npm test             # 見出しの読み取り・振り分けのテスト
```

編集するのは `site/` です。**`docs/` の中身は直接編集しないでください**（次のビルド・収集で上書きされます）。

## 画面の構成

| 場所 | 内容 |
| --- | --- |
| LIVE（ティッカー） | 新着の見出しが横に流れる。マウスを乗せると止まる |
| 抽選・予約の受付（LOTTERY BOARD） | 抽選・予約・先着の記事を、受付状況（本日締切 / 受付中 / 受付前 / 情報 / 締切）と締切の近い順に並べる。店舗で絞り込める |
| 注目の話題 | 複数の媒体が同じことを報じたもの |
| 新着ニュース | ゲーム（ポケカ / ポケポケ / 海外）と種別（抽選・予約 / 再販・入荷 / 新弾・新商品 / 新カード / 大会・イベント / プロモ・特典 / 相場・買取 / デッキ・攻略 / 注意喚起・事件 / サプライ・グッズ）で絞り込める。記事の店舗・商品のタグを押すとその店・商品だけになる |
| これからの予定（CALENDAR） | 見出しの「10月17日発売」「10/12まで受付」のような日付を日付順に並べる |
| 商品別・店舗別 | 商品名・店名ごとのページへのリンク |
| 見たくないことば | 含む記事を一覧・ボード・ティッカーから隠す |

右上のボタンで暗い表示と明るい表示を切り替えられます（最初は暗い表示）。

## 収集のしくみ

| 収集元 | 内容 |
| --- | --- |
| ポケモンカードゲーム公式のお知らせ（`pageLists`） | RSS が無いので、お知らせ一覧のページから `linkPattern` に当たるリンクの見出しだけを拾う。公式サイトの作りが変わると 0 件になるだけで、ほかの収集は止まらない |
| ポケモンカードチャンネル（YouTube の RSS） | 公式の動画。新弾の紹介・新カードの公開が多い |
| Google ニュースの検索フィード | `config.json` の `googleNews.queries`（16 クエリ）。**掲載件数の大半はここから来る** |
| ゲーム・ホビー媒体・プレスリリースの RSS | 4Gamer / Game*Spark / インサイド / 電ファミ / AUTOMATON / GAME Watch / IGN Japan / 電撃ホビーウェブ / ねとらぼ / PR TIMES。総合フィードなので、ポケカに関係するものだけを残す（`keywords`） |

絞り込みは pokematome と同じ流れです。公開から 7 日を過ぎたもの、画像ギャラリー・ショップの商品ページ・SNS の投稿（`blockTitlePatterns` / `blockSources`）、見出しが日本語でないもの、キーワードに当たらないものを落とし、見出しを正規化して重複をまとめます。`officialHosts` のドメインの記事には「公式」の印を付けます。

### 同じ型の記事が流れ込みすぎないように（`caps`）

Google ニュースには、スニーカーダンクの「〇〇の買取・相場価格と値段推移」や GameWith の「【ポケポケ】〇〇デッキのレシピと評価」のように、毎日「更新」されて新着として流れてくるページが大量に混ざります（実際の収集で 1 日 20 件以上）。そこで媒体（`host`）ごと・見出しの型（`pattern`）ごとに、新しいものから `max` 件だけ残します。公式の発表は数えません。

## 抽選ボード・予定・商品名の読み取り（`scripts/lib/extract.mjs`）

どれも見出しのことばを規則で読んでいるだけなので、まちがうことがあります。画面には「見出しから読み取った締切です。必ずリンク先で確かめてください」と出しています。

- **締切**: 「10月12日（日）23:59まで」「10/10〜10/14」「締め切りは10月20日」「本日締切」など。範囲は後ろを締切・前を受付開始とする
- **予定**: 日付のすぐ後ろの語で種類を決める（発売 / 再販・入荷 / 予約開始 / 抽選・受付 / 締切 / 開催 / 配信・公開）。「【9/24更新】」のような記事の更新日は使わない。年が書かれていない日付は、記事が出た日から近いほうの年にする（年末の記事の「1月」は翌年）。まとめ記事の「【1/20発売】」は何年も前の商品のことが多いので、60 日より先の日付は信じない
- **店舗**: `config.json` の `stores`。見出し・要約・媒体名に店名が出てきたらその店の情報とする（ショップのブログは媒体名が店名）
- **商品名**: 「拡張パック「〇〇」」のように、商品の種類のすぐ後ろのかぎかっこを商品名として覚え、`data/products.json` に貯める。1 度覚えた名前は、かっこ無しで書かれた見出し（「〇〇の再販はいつ？」）からも拾う。表記ゆれは `productAliases` でまとめる

抽選ボードと予定は、7 日より前の記事に書かれていることも多いので、`data/archive/` に貯めた記事（抽選は 21 日、予定は 120 日さかのぼる）からも作ります。

## 更新の間隔について

**GitHub Actions の cron は当てになりません**（pokematome の README を参照。10 分おきに置いても数時間走らないことがある）。

そこで**更新の主役は外部トリガー**にしています。ロリポップの cron から、trend-video-watcher リポジトリにある `tools/trigger-collect.php` を実行します。**このサイトを動かすには、スクリプトの `REPOS` に `lumieregiurare-ops/pokecardmatome` を足してください。**

```bash
curl -X POST -H "Accept: application/vnd.github+json" -H "Authorization: Bearer <TOKEN>" \
  https://api.github.com/repos/lumieregiurare-ops/pokecardmatome/dispatches \
  -d '{"event_type":"collect"}'
```

cron は配信されたとき用のフォールバックとして 10 分おきに置き、**前回の収集から 25 分たっていなければ即座に終了する**ガードを入れてあります（前回の時刻は `data/state.json` の `ranAt`）。

## 公開の設定（ロリポップ）

**Secrets**: `LOLIPOP_FTP_SERVER` / `LOLIPOP_FTP_USER` / `LOLIPOP_FTP_PASSWORD`
**Variables**: `DEPLOY_TARGET` = `lolipop`、`LOLIPOP_SERVER_DIR` = サブドメインの公開ディレクトリ（例 `./pokecard/`。末尾のスラッシュ必須）

サブドメインは仮に `pokecardmatome.gamelab.website` にしています。変える場合は `config.json` の `site.url`、`site/index.html` の OGP・canonical、`site/robots.txt`、`scripts/make-og.py` を直してください（sitemap.xml は自動で作られます）。

Google アナリティクスを入れる場合は、`config.json` の `site.gaId` に測定 ID（`G-` で始まるもの）を入れてください。全ページの `<head>` に入ります。

## 検索エンジン向けのページ（SEO）

トップの画面は `app.js` が `news.json` を読んで描くので、それだけだと検索エンジンには中身が見えません。そこで、収集（`collect.mjs`）とビルド（`build.mjs`）の最後に `scripts/lib/pages.mjs` が次のものを `docs/` に書き出します。

| URL | 内容 |
| --- | --- |
| `/` | `site/index.html` の `<!--ssr:…-->` に、抽選ボード・予定・新着 30 件・サイト内リンク・構造化データを差し込んだもの（表示後は app.js が描き直す） |
| `/lottery/` | 抽選・予約の受付（ボード全件）と抽選・予約のニュース |
| `/schedule/` | これからの予定（月ごと） |
| `/set/` `/set/<商品>/` | 商品別。発売日（記事から）・受付中の抽選・予定・ニュース |
| `/store/` `/store/<店舗>/` | 店舗別。抽選・予約とニュース |
| `/tcg/` `/pocket/` `/global/` | ゲーム別（`pages.series`） |
| `/news/<種別>/` | ニュースの種別（`pages.genres`） |
| `/archive/…` | 過去ログ（月別・日別） |
| `/about/` `/404.html` `/feed.xml` `/sitemap.xml` | サイトについて・404・Atom フィード・サイトマップ |

- サブページのヘッダー・フッターは `site/index.html` から切り出して使います。見た目を変えるときは index.html を直せば、サブページにも反映されます
- 過去の記事は `data/archive/YYYY/MM/DD.json`（日本時間の日付ごと）に貯めています。`news.json` は 7 日で消えますが、こちらは消えません
- 記事が 3 件未満のページは `noindex` にして sitemap にも載せません
- 中身が変わったファイルだけを書き直すので、FTP で送られるのも変わったページだけです

## 手元での確かめ方（外へつながらない環境）

`COLLECT_FIXTURE` に記事の配列（`fetchAll` が返す形の JSON）を渡すと、ネットワークを使わずにそれを読んで、絞り込み・抽選ボード・ページ生成まで流します。

```bash
COLLECT_FIXTURE=path/to/items.json node scripts/collect.mjs
```

最初に入れてある `data/archive/` は、pokematome が 2026-09-21 から実際に集めた記事のうち、ポケカに関係するものをこの仕組みで振り分け直したものです。

## ブラウザに保存しているもの

| キー | 内容 |
| --- | --- |
| `pkc:fav` | 「あとで読む」に入れた記事 |
| `pkc:read` | 開いた記事（一覧で薄く表示する） |
| `pkc:state` | 選んでいるゲーム・種別・店舗・商品・ボードの表示 |
| `pkc:ng` | 見たくないことば |
| `pkc:theme` | 暗い表示 / 明るい表示 |

**localStorage にだけ**保存しています。サーバーには何も送りません。
